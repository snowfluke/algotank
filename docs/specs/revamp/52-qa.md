# Work package QA: full browser test of the production build

Read `00-overview.md`. Every earlier check ran on the Vite dev server. This package tests what a visitor gets: the built client served by the Bun server. You find problems, fix the small ones, and report the rest.

## Setup

- `bun test && bun run type-check && bun run build`.
- Serve the build: `PORT=8947 DATA_DIR=<a directory you make with mktemp -d under the scratchpad> bun apps/server/src/index.ts` in the background (record the PID). The client is served from the same port. No Vite.
- Playwright, headless Chromium, one browser at a time: `import { chromium } from "<a Playwright installation>/index.mjs"`. The scripts in `<scratchpad>/revamp/w2/` (`private-flow.mjs`, `presenter-flow.mjs`, `public-flow.mjs`) and `<scratchpad>/revamp/w3b/run.mjs` drive the flows on the dev server; adapt them. Scripts and screenshots go to `<scratchpad>/revamp/qa/`. The scratchpad is the builder's scratch folder.

## Also check

- Text: no English left in the Indonesian interface, no raw ids, no placeholders, no clipped or overflowing text at 390 px (use a 24-character player name and a 40-character arena name).
- Contrast: compute the contrast of text against its background for the main text styles on five representative pages; report any under 4.5:1.
- Touch targets under 44 px on the phone pages.
- The fonts load from the server itself (no request leaves the origin on any page).
- Response headers of the HTML and of an API answer: note missing basics (content type, cache control for the HTML, no sniff). Do not add a framework; fix what is one line.

## Fix or report

Fix a problem when the fix is small and local (a wrong class, a missing key, an overflow, a broken link) and re-run the flow that showed it. Report anything larger with the screenshot, the steps, and the file you believe is responsible. Do not redesign.

## Report

- A table: flow, result, problems found, fixed or open.
- The open problems, most severe first, each with a screenshot path and steps.
- 12 screenshots you consider the best evidence of the game's current state (paths), covering home, play now, the preparation tabs, a running round on a phone, the big screen running and at the end, and a result.
- The commands you ran with results, and the processes you started and stopped.
